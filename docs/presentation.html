ארכיטקטורת רכיבים — High Level

שרת–לקוח בשכבות: הלקוח הגרפי פונה לשרת בפרוטוקול TCP עם הודעות JSON. השרת מנתב לבקרים, השירותים מחזיקים את הלוגיקה העסקית, והמאגר והאלגוריתמיקה נצרכים דרך ממשקים.

03 · שקופית שלישית

אתגרים בפיתוח

האתגרים המרכזיים שעמדנו מולם, וההחלטות התכנוניות שפתרו אותם.

מידול השיבוץ כבעיית זרימה ברשת

תרגום דרישות תפקיד, זמינות עובדים ואילוצים לגרף מקור–בור, כך שאלגוריתם Max Flow מפיק שיבוץ תקף וממוקסם.

שני מימושים מתחלפים באמצעות Strategy

הפשטת ה־API ל־IAlgoMaxFlow כך ש־Ford-Fulkerson ו־Edmonds-Karp ניתנים להחלפה מבלי לשנות את שכבת השירות — שמירה על עקרון Open/Closed.

אילוצים קשיחים מול העדפות רכות

הפרדה בין ולידציה (מותר / אסור) לבין ניקוד (טוב יותר / פחות), כדי לאפשר הוספת אילוצים והעדפות בעתיד ללא שינוי הליבה.

פרוטוקול תקשורת גנרי

עיצוב Request / Response מבוססי JSON שאינם תלויים בשפת המימוש, עם ניתוב דינמי של בקרים באמצעות Factory.

הפרדת לקוח–שרת נקייה

הלקוח הגרפי מכיל אך ורק רכיבי UI ותקשורת Socket — כל הלוגיקה העסקית מתבצעת בצד השרת.

אחסון מבוסס קבצים עם גנריות

מימוש IDao<T> מעל streams עטופים ב־Decorator, לשמירה ושליפה גנרית של כל מודל נתונים ללא בסיס נתונים.
